이번에 고친 문제
- 3D 봇의 상태 변화를 모두 "성공"으로 기록해서, 하늘섬에서 **떨어져 다시 나타난 순간**과 드래곤 **보스 등장**이 "해냈다!" 자막 후보가 되던 문제 → 상태 이름으로 성공(클리어 · 체크포인트) · 실패(게임 오버 · 떨어짐)만 구분, 그 밖은 자막 없음. 3D 클립 3개를 다시 녹화.
- 검수에 크기가 다른 영상(가로 등)이 들어오면 게임 영역 자르기에서 FFmpeg 가 멈춰 검수 자체가 죽던 문제 → 크기가 다르면 영역 검사를 건너뛰고 불합격 사유로 남김.
- "게임 영역 절반 이상 움직임" 기준이 반응 게임(신호를 기다리는 화면이 게임)에 너무 엄격 → 20% 로 낮추고 설정(`qc.minMotion`)으로. 2초 이상 완전히 멈추면 실패하는 검사는 그대로.
- 문구에 사이트 설명의 긴 PC 조작법 문장("컴퓨터에서는 …")이 들어가던 것 → 60자 이하 · 휴대폰에도 맞는 문장일 때만.

## 확인하지 못한 것

- **실제 Claude 호출**: `LLM_API_KEY` 가 없어 안 해 봄. 요청 형식(모델 · 구조화 출력 · `fallbacks`)은 가짜 클라이언트로만 확인 — 실제 API 가 이 형식을 받는지는 키를 받은 뒤 확인.
- 배경음악: 허용 목록이 비어 있어 넣지 않음 (게임 원래 소리만). 후보 `assets/audio/hip/*.mp3`(CC0) — 관리자가 허용 목록을 정하면 추가.
- **같은 게임을 다시 녹화하면 거의 같은 장면** (봇 · 게임이 결정적 — 용암 서핑 점수 흐름이 두 번 모두 같음). 같은 게임을 다시 홍보할 때 영상이 비슷해짐 → 다른 스테이지 · 하이라이트 구간 돌리기 등 PHASE 5 에서.
- 하늘섬 원본에 구름 속 하얀 몇 초가 있음 — 이번 하이라이트에는 안 걸림. 하얀 화면 검사는 없음 (검은 화면만).
- 커버 글자가 게임 화면 위에 얹힘 (가독성은 눈으로 확인, 위치 자동 조정 없음).
- GitHub Actions 위에서 편집 시간 · 한글 표시 (PHASE 5).
